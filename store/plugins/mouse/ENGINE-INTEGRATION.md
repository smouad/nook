# Mouse engine integration

Third-party engine attribution and license details are recorded in
`THIRD_PARTY_NOTICES.md` at the repository root and `upstream/License` in this package.
The pinned revision is `603646cdb5200eb9d0db0afdb5967c7ec41c5de0`.
Original file hashes and source locations are recorded in `upstream/sources.json`.
`python3 store/plugins/mouse/verify-upstream.py` verifies them without network access.

## Code boundary

Original acceleration Beziers, fast-scroll curve, linear/Bezier hybrid and drag curves,
tick/swipe analysis, rolling average and circular buffer compile into the Mouse helper.
The original ClickCycle supplies click/hold/multi-click timing and recognition.
Adapters provide the narrow upstream Objective-C/Swift ABI, Nook's configuration and JSON-RPC,
supervised process lifetime, event tap, display-link scheduling and generated input.
System-shortcut resolution follows upstream while honoring the active keyboard layout.
The original action and scroll configuration sources are included for comparison.

This replaces the earlier hand-translated core algorithms. It is not the entire upstream app
or a claim that every input/output sequence is byte-identical to its standalone helper.
No original app, login item, updater or separate permanent daemon is installed.

## Matching the original settings

**Restore defaults** applies the source's high smoothness, medium speed, reversed direction,
trackpad simulation, Shift for sideways scrolling, Option for precise scrolling,
Control for quick scrolling, and Command for zooming. It also applies the original
three-button middle mapping and five-button back/forward mappings. It preserves the
Enable switch and additional configured buttons. Mouse button numbers are one lower
in CGEvent/Nook than in the upstream engine's configuration.

The Speed selector supports the upstream engine's low, medium and high tables and macOS-provided
pixel distances. Custom retains Nook's older speed multiplier and acceleration slider.
Existing settings migrate to Custom; applying the preset explicitly chooses the default
values. New settings use the preset with mouse interception disabled.

## Deliberate integration differences

- Low smoothness uses the author's documented experimental cubic. The released
  ScrollConfig disables that branch with `fatalError`; Nook never invokes it.
- Unavailable system shortcuts are reported. Nook does not enable or rewrite macOS
  keyboard shortcuts. Mission Control and Launchpad can fall back to opening the app.
- Nook keeps its button editor, extra actions, optional wheel-chatter filter and Classic
  scroll output. Device-specific HID filtering and modifier-conditioned/multi-button
  remap editing from the original app are not implemented by this editor. All physical
  mice currently share one logical button-device identity. the upstream engine's single active click
  recognizer cancels the previous pending click when another button begins a cycle;
  Nook still balances every physical release and pointer freeze independently.
- Input/output remains Nook's adapter, including its immediate first frame. Drag/swipe
  gestures use adapted upstream event layouts. Actual mouse feel and private gesture behavior
  must still be checked on real hardware; no automated desktop input is generated by tests.

## Build and check

From the Nook repository:

```sh
python3 store/plugins/mouse/verify-upstream.py
bash tests/mouse/run.sh
bash store/plugins/mouse/build.sh
python3 tests/engine/mouse-protocol.py store/plugins/mouse/bin/helper /tmp/nook-mouse-protocol-check
nook validate store/plugins/mouse
```

The build compiles original Swift and Objective-C for arm64 and x86_64 and signs a
universal helper. Tests exercise real upstream calculations, deterministic event replay,
button timing, in-memory event fields, the web editor and isolated RPC/config persistence.
They do not install an event tap or post keyboard/mouse input. Runtime `mouse.state`
and `bin/helper --probe` include the pinned engine revision.
